# 변경 요청 — 이 견적, 보내도 됩니까?

## 승인된 제작 범위

CXO 대상의 사전 제작 데모. 준비된 합성 견적 앱에 **최저 매출총이익률 15% 미만 견적 모의 전송 차단** 한 가지 기능을 추가한다. 이 문서는 제작 계획에서 승인받은 구현 범위이며, 구현 결과의 수용 또는 운영 배포 승인이 아니다. 별도 승인을 받은 것처럼 대화를 만들지 않는다.

## 업무 규칙

- 매출총이익률 = (할인 후 견적액 − 서버에 등록된 원가) ÷ 할인 후 견적액.
- 15% 미만이면 UI에 차단 이유를 표시하고 모의 전송 버튼을 비활성화한다.
- 15%와 같거나 높으면 모의 전송을 허용한다.
- `POST /api/send`에서도 같은 규칙을 검사한다. 미달은 HTTP 422, 오류 코드 `MARGIN_BELOW_MINIMUM`. 실제 외부 발송은 없다.
- 정책 기준은 서버가 소유한다. 클라이언트가 가격·원가·계산된 마진·기준값을 보내는 요청은 거절한다.
- 원 단위 정수·할인 basis point와 기존 반올림 규칙을 재사용한다. 표시용 이익률 반올림값으로 판단하지 않는다. `profitWon * 10000 >= netWon * 1500` 같은 정확한 정수 비교를 사용한다.
- 서버의 미리보기 결과에 판정과 기준을 포함하고 UI는 서버 판정을 표시한다. UI와 서버에 상충하는 정책을 복제하지 않는다.

## 완료 기준

1. Q-1001, 할인 10%: 순매출 9,000,000원, 이익 1,000,000원, 약 11.1% → 차단.
2. Q-1001, 할인 0%: 순매출 10,000,000원, 이익 2,000,000원, 20% → 허용.
3. Q-1500, 할인 0%: 정확히 15% → 허용.
4. Q-1499, 할인 0%: 표시상 15.0%가 될 수 있으나 원가 8,500,001원 → 차단.
5. Q-1501, 할인 0%: 15% 초과 → 허용.
6. 버튼을 사용하지 않은 직접 API 요청에도 미달 차단.
7. 잘못된 할인, 순매출 0, 위조 추가 필드, 알 수 없는 견적 ID → 기존 입력 검증 유지.
8. 기존 정상 계산과 정상 모의 전송, 로컬 실행, 작은 화면 접근성을 유지.
9. 신규 테스트 및 기존 테스트를 실제 실행. 실행하지 않은 것은 미검증이라고 표시.

## 변경 허용과 제외

허용: `src/quote.mjs`, `src/server.mjs`, `public/index.html`, `public/app.js`, `public/style.css`, `test/margin.test.mjs`.

기존 테스트를 약화하거나 삭제하지 않는다. 새 의존성·외부 네트워크·DB·인증·실제 발송·Git 초기화·commit·PR·push·배포·설정 변경은 제외한다. 작업 공간 밖의 완성 참고본을 읽거나 복사하지 않는다.

## 전달할 근거

계획은 실제 파일/함수와 변경 이유를 명시한다. 구현 기록에는 실제 수정 파일과 테스트 명령/종료 상태를 남긴다. 검토 역할은 이 요청, 실제 코드, diff, 테스트 로그를 함께 읽고 기준별 충족·미충족·미검증을 구분한다. 검토 의견은 사람의 승인이나 독립 감사가 아니다.
