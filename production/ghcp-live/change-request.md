# 이 견적, 보내도 됩니까?

## 업무 요청

회사에서는 매출총이익률 15% 미만인 견적을 고객에게 보내지 않기로 했습니다. 이 규칙을 현재 견적 앱에 적용해 주세요. 기준 미달이면 화면에 이유를 표시하고 모의 전송을 막되, 정상 견적의 업무 흐름은 유지해야 합니다.

이 앱의 모든 고객·금액은 합성 데이터입니다. 전송은 모의 처리이며 외부 발송은 없습니다. 이번 작업은 기존 앱에 업무 규칙 하나를 추가하는 로컬 데모입니다.

## 인수 기준

- 매출총이익률은 할인 후 견적액에서 등록 원가를 뺀 금액을 할인 후 견적액으로 나눈 비율입니다.
- 15% 미만이면 모의 전송을 차단하고 이유를 표시합니다. 정확히 15%이거나 높으면 허용합니다.
- 화면을 거치지 않고 전송 API를 직접 호출해도 같은 규칙을 적용합니다. 미달 요청의 응답은 HTTP 422, 오류 코드는 `MARGIN_BELOW_MINIMUM`이어야 합니다.
- 기준 금액·원가·정책은 서버가 소유합니다. 클라이언트가 이를 임의로 보낸 요청을 받아들이지 않습니다.
- 화면에 반올림해 표시하는 비율이 아니라 실제 금액에 따른 비율로 판정합니다. 기존 정수 금액·할인 단위·반올림 규칙은 유지합니다.
- UI의 표시와 서버의 판단이 일치해야 합니다.

| 사례 | 기대 결과 |
| --- | --- |
| Q-1001, 할인 10% | 견적액 9,000,000원, 이익 1,000,000원, 약 11.1%: 차단 |
| Q-1001, 할인 0% | 매출총이익률 20%: 허용 |
| Q-1500, 할인 0% | 정확히 15%: 허용 |
| Q-1499, 할인 0% | 기준보다 원가가 1원 높음: 표시가 15.0%여도 차단 |
| Q-1501, 할인 0% | 기준 초과: 허용 |
| 위조 필드·잘못된 할인·순매출 0 | 기존 입력 검증 및 HTTP 400 유지 |
| 존재하지 않는 견적 ID | 기존 HTTP 404 유지 |
| 빠른 입력 변경·지연 응답 | 이전 입력의 결과로 전송 허용이나 성공 메시지가 남지 않음 |
| 작은 화면 | 가로 넘침 없이 기존 업무 흐름 유지 |

## 진행과 승인

먼저 현재 코드와 기존 테스트를 조사해 변경 범위·검증 방법을 제안해 주세요. 구현하기 전에 사용자의 실제 승인을 기다립니다. 이 문서가 있다는 것 자체는 구현 승인이나 도구 실행 허가가 아닙니다.

승인 후에는 업무 규칙을 확인하는 회귀 테스트를 먼저 추가해 미구현 상태의 실패를 확인하고, 실제 수정 후 전체 테스트를 다시 실행합니다. 없는 함수의 import 오류나 문법 오류를 업무 규칙의 실패로 설명하지 않습니다.

실제 실행한 명령과 결과만 보고하고, 실행하지 못한 검증은 미검증으로 구분합니다. 결과 채택·배포 승인은 별도입니다.
