```sh
open "deliverables/ghcp-cxo-demo-ko.mp4"
```

### 발표 직전 2분 확인

1. 실제 사용할 컴퓨터에서 MP4의 시작·중간·끝을 재생하고 음량과 한국어 자막을 확인합니다.
2. 전체 화면과 화면 공유를 확인합니다. 개인정보가 있는 창과 알림은 정리합니다.
3. 인터넷 연결 없이도 MP4가 재생되는지 확인합니다. **오프라인 상영**과 **Copilot 개발 실행**은 다릅니다. Copilot을 새로 실행하는 작업은 로그인·네트워크 등이 필요할 수 있습니다.
4. 질문에 대비해 PPT의 7장 결과, 8장 실행 근거, `production/facts.json`을 준비합니다.
5. 코드·근거·캡처가 검증 당시 버전과 같은지 확인합니다. 코드가 바뀌었다면 이전 영상의 근거를 현재 코드의 검증으로 설명하지 않습니다.

**5분 운영:** 영상을 주 발표로 사용하세요. PPT 12장을 모두 설명한 뒤 영상을 추가하면 5분을 넘습니다. PPT는 영상 대신 설명하거나 질문에 답할 때 사용하는 선택 자료입니다.

발표 시작 한 문장:

> 기존 견적 앱에 업무 규칙 하나를 추가한 실제 개발 사례입니다. 합성 데이터와 모의 전송을 사용한 사전 제작 영상으로, 사업 요청이 코드와 실행 근거로 연결되는 과정을 보겠습니다.

## 무엇을 보여 주는가

기능은 한 가지입니다. **매출총이익률이 15% 미만인 견적의 모의 전송을 차단합니다.** 정확히 15%이거나 높으면 허용합니다. 화면에 차단 이유를 표시하고, 서버도 같은 기준을 검사합니다.

매출총이익률은 `(할인 후 견적액 − 서버에 등록된 원가) ÷ 할인 후 견적액`입니다. 할인 전 판매가를 분모로 쓰지 않습니다.

| 사례 | 입력과 계산 | 변경 후 기대 결과 |
| --- | --- | --- |
| 기준 미달 | Q-1001, 할인 10%. 판매가 10,000,000원, 원가 8,000,000원 → 견적액 9,000,000원, 이익 1,000,000원, 약 11.1% | 차단 이유 표시, 모의 전송 버튼 비활성화 |
| 정상 업무 | Q-1001, 할인 0% → 견적액 10,000,000원, 이익 2,000,000원, 20% | 모의 전송 허용. 외부 발송 없음 |
| 정확히 기준 | Q-1500, 할인 0%. 견적액 10,000,000원, 원가 8,500,000원 → 이익률 15% | 허용 |
| 반올림 경계 | Q-1499, 할인 0%. 원가 8,500,001원 → 이익 1,499,999원, 이익률 14.99999% | 표시가 15.0%여도 차단 |
| 기준 초과 | Q-1501, 할인 0%. 원가 8,499,999원 → 이익률 15.00001% | 허용 |
| 직접 서버 요청 | Q-1001, 할인 10%로 `POST /api/send` | HTTP 422, 오류 코드 `MARGIN_BELOW_MINIMUM` |

위 표는 완료 기준입니다. 실제 확인 여부는 `production/facts.json`과 연결된 테스트·브라우저·API 기록을 읽고 판단합니다. 표 자체가 실행 증거는 아닙니다. 원가는 서버의 준비된 견적 데이터이며 화면에서 임의로 수정하지 않습니다. 경계값은 각각의 견적 ID를 선택합니다.

## 준비물과 실제 실행을 구분하세요

| 경로 | 의미 |
| --- | --- |
| `demo/starter/` | 계산·입력 검증·모의 전송이 있는 **미리 준비한 합성 시작 앱**. 15% 차단 규칙은 없음 |
| `docs/change-request.md` | 변경 범위·완료 기준·제외 사항. 사후 채택 승인을 뜻하지 않음 |
| `demo/run/` | 시작 앱에서 실제 Copilot CLI 구현을 진행한 작업본 |
| `evidence/copilot-run/` | Copilot 구현·권한 거절, 별도 로컬 검증, 읽기 전용 검토의 기록. 정확한 위치는 `facts.json`의 `evidenceDir` 우선 |
| `production/facts.json` | 실제 구현·검토 여부, 별도 로컬 테스트·브라우저·API 확인 건수, 코드 식별값, 검토 상태, 제약 |
| `production/screenshots/` | 실제 화면 캡처 `before.png`, `blocked.png`, `allowed.png`, `boundary.png` |
| `demo/fallback/` | 주 제작 과정에서 별도로 보존하는 검증된 변경본. 실제 존재 여부와 검증 계보를 확인한 뒤 사용 |

시작 앱 전체를 Copilot이 이번에 처음부터 만들었다고 말하지 않습니다. 실제 도구는 **Copilot CLI**입니다. VS Code UI를 시연·검증했다고 말하지 않습니다. 영상에는 실제 앱 화면과 실행 기록을 사용하지만 대기 구간이 편집되어 있으며, 내레이션은 한국어 합성 음성입니다. 재생 길이가 개발 소요시간이나 생산성 향상을 뜻하지 않습니다.

### 실행 주체와 근거

> **Copilot 구현 → 별도 로컬 검증 → Copilot 읽기 전용 검토 → 사람의 채택 판단**

이번 Copilot 구현 중 `node --test`는 **권한 거절로 실행되지 않았습니다.** 이후 사용자가 **별도 로컬 테스트·브라우저 검증을 승인**했으며, 통과 건수는 그 별도 실행의 근거입니다. Copilot이 테스트를 실행·통과시켰거나 거절을 자동 우회한 사례로 설명하지 않습니다. 권한 거절과 별도 승인 자체가 사람이 실행 범위를 통제한 지점입니다.

아래 표는 제작 환경의 원본 경로 `evidence/copilot-run/` 기준입니다. **비공개 저장소 클론에서는 `implement.log`, `review.log`, `local-test-record.json`을 `evidence/shareable/copilot-run/`에서 읽으세요.** 세션 ID와 개인 절대 경로를 가린 사본이며, 원본은 로컬에만 보존했습니다. 나머지 표의 파일은 `evidence/copilot-run/`에 있습니다. [원본·사본 구분](../evidence/copilot-run/README.md)과 [최종 검수 한계](production-status.md)를 함께 확인하세요.

| 파일 | 확인할 내용 |
| --- | --- |
| `implement.log` | 실제 Copilot 구현과 테스트 실행 권한 거절 |
| `local-tests.log` | 별도 로컬 테스트의 출력 |
| `local-test-record.json` | 별도 로컬 테스트 실행 기록 |
| `browser-checks.json` | 실제 브라우저 동작 확인 기록 |
| `api-responses.json` | 직접 API 요청과 응답 기록 |
| `review.log` | Copilot 읽기 전용 검토 기록 |
| `changes.diff` | 시작 앱 대비 실제 코드 변경 |

`facts.json`에 없는 통과 건수·검토 결론·사람의 승인을 임의로 추가하지 않습니다. `copilotImplementation`과 `copilotReview`를 구분합니다. 읽기 전용 검토 의견은 **독립 감사 또는 사람의 승인**이 아닙니다. 시작 앱 테스트와 변경 후 테스트의 건수를 더해 하나의 고유 테스트 수라고 부르지 않습니다. `browserChecks.passed`에는 UI와 직접 API 확인이 함께 집계될 수 있으므로 **브라우저·API 확인**이라고 표시합니다. 수치는 실제 기록이 완성된 뒤 `facts.json`에서만 가져옵니다.

## 사람의 통제와 최종 판단

- **H1 — 구현 전 범위 확인:** 사람이 요청과 완료 기준, 수정 범위와 제외 사항을 확인합니다. 이번 제작의 범위 문서와 실제 실행 기록을 근거로 설명하며, 승인 채팅이나 버튼을 만들어 보여 주지 않습니다.
- **H1과 H2 사이 — 별도 로컬 검증 승인:** Copilot 테스트 실행 권한 거절 뒤, 사용자가 별도 로컬 검증을 승인한 단계입니다. H1만으로 모든 실행 권한을 받았거나 테스트 통과로 H2까지 승인된 것처럼 연결하지 않습니다.
- **H2 — 결과 채택 판단:** 사람이 요구사항, 변경 코드, 실행 근거와 남은 제약을 읽고 결과를 받아들일지 판단합니다. **최종 채택은 아직 미결정이며 운영 배포 승인도 남아 있습니다.**

이 앱의 견적 판정은 결정적 서버 코드입니다. 매 견적마다 LLM이 판단하는 구조가 아닙니다. Copilot Studio 솔루션이나 A2A 프로토콜을 구현한 시연도 아닙니다. 외부 발송, DB, 인증, 운영 배포는 이번 작은 변경의 범위가 아닙니다.

## 선택 사항 — 현장에서 앱을 직접 보여 주기

영상만 보여 주면 아래 작업은 필요 없습니다. 라이브 앱을 추가로 열 경우 Node.js 22 이상과 제작된 `demo/starter`, `demo/run` 파일을 먼저 확인합니다. 설치·Copilot 재실행·구현 반복은 발표 중 하지 않습니다.

두 개의 터미널에서 각각 프로젝트 최상위 폴더를 기준으로 실행합니다. 아래는 macOS/Linux 셸용 명령이며, `PORT=...`는 npm 인자가 아니라 앞에 붙이는 환경 변수입니다.

**변경 전 시작 앱, 포트 4310:**

```sh
PORT=4310 npm --prefix demo/starter start
```

브라우저에서 `http://127.0.0.1:4310`을 엽니다.

**변경 후 작업본, 포트 4311:**

```sh
PORT=4311 npm --prefix demo/run start
```

브라우저에서 `http://127.0.0.1:4311`을 엽니다. 주소를 확인해 시작 앱과 혼동하지 마세요. 서버는 localhost 전용이며 외부 공개를 위해 주소나 방화벽을 바꾸지 않습니다.

**4310 또는 4311이 이미 사용 중이면 알 수 없는 프로세스를 종료하지 마세요.** 사용 가능한 다른 포트를 골라 `PORT`만 바꿉니다. 예를 들어 4410·4411이 비어 있다면 각 터미널에서 다음과 같이 실행합니다.

```sh
PORT=4410 npm --prefix demo/starter start
PORT=4411 npm --prefix demo/run start
```

이 경우 브라우저 주소도 각각 `http://127.0.0.1:4410`, `http://127.0.0.1:4411`로 바꾸고, 아래 `curl` 요청의 `4311`도 `4411`로 바꿉니다. 다른 포트 역시 사용 중이면 빈 포트를 선택하거나 MP4만 상영하세요.

### 짧은 라이브 순서

1. **변경 전 시작 앱:** Q-1001에서 할인 10%를 입력합니다. 약 11.1%이지만 모의 전송이 가능한 준비된 시작 동작을 보여 줍니다.
2. **변경 후 작업본:** 같은 Q-1001, 할인 10%를 입력합니다. 이유 표시와 전송 버튼 비활성화를 보여 줍니다.
3. **정상 업무:** 할인율을 0%로 바꾸고 20%를 확인합니다. 모의 전송을 누르면 외부 발송 없이 성공합니다.
4. **경계값:** Q-1500, 할인 0%는 허용됩니다. Q-1499, 할인 0%는 표시상 15.0%여도 차단됩니다. 원가가 1원 높은 별도 합성 견적임을 설명합니다.
5. **필요할 때 서버 확인:** 아래 직접 요청이 차단되는지 보여 줍니다. 요청 필드에는 견적 ID와 할인율만 보냅니다. 작업본에 실제로 선택한 포트를 사용하세요.

```sh
curl -i -sS -X POST http://127.0.0.1:4311/api/send \
  -H 'Content-Type: application/json' \
  --data '{"quoteId":"Q-1001","discountBps":1000}'
```

기대 응답은 **HTTP 422**와 **`MARGIN_BELOW_MINIMUM`**입니다. `discountBps: 1000`은 할인 10%입니다. 정상 요청을 확인하려면 `discountBps`를 `0`으로 바꿉니다. 기대 응답은 HTTP 200과 `sent: true`, `simulation: true`이며 실제 발송은 없습니다.

### 문제가 생기면 녹화 영상으로 전환

- 다른 결과가 보이면 성공한 것처럼 설명하지 말고 라이브를 중단합니다. 주소, 입력, 실행 버전을 발표 뒤 확인합니다.
- 다음과 같이 말하고 MP4를 엽니다: **“지금부터는 사전에 검증해 녹화한 실행 화면입니다. 현재 화면의 라이브 실행과 구분해서 보시겠습니다.”** 이 표현은 최종 MP4의 근거·재생 검수가 끝난 경우에만 사용합니다.
- 로그인을 새로 시도하거나 도구 권한을 넓히고 코드를 고치는 작업은 발표 중 하지 않습니다.
- 서버 종료는 본인이 띄운 해당 터미널의 `Ctrl+C`로만 합니다. 포트 번호만 보고 다른 프로세스를 종료하지 않습니다.
- `demo/fallback/`이 실제로 있고 최종 검증본임을 확인한 경우에만 아래와 같이 별도 보관본을 실행할 수 있습니다. **복구용 보관본 실행**이라고 명시하고 새 Copilot 구현이라고 부르지 않습니다. 예시의 4412도 비어 있는지 확인하고, 사용 중이면 다른 `PORT`를 선택합니다.

```sh
PORT=4412 npm --prefix demo/fallback start
```

보관본 브라우저 주소는 예시에서 `http://127.0.0.1:4412`입니다. 원본·작업본·근거를 지우거나 강제 리셋할 필요는 없습니다. 종료할 때는 본인이 시작한 서버 터미널 각각에서 `Ctrl+C`를 누릅니다.

## PPT를 사용할 때

슬라이드의 제목·본문·규칙·도형은 PowerPoint에서 편집할 수 있습니다. 앱 캡처만 이미지이며 전체 슬라이드를 이미지로 만든 자료가 아닙니다. 각 장의 발표자 노트에는 말할 내용과 사실 구분 지침이 있습니다.

| 장 | 용도 | 강조할 말 |
| --- | --- | --- |
| 1 | 소개 | 기존 앱의 작은 요청 하나 |

## 제작자용 — 실제 근거가 준비된 뒤 슬라이드 생성

이 명령은 MP4를 다시 만드는 명령이 아닙니다. 실제 Copilot 구현, 사용자 승인에 따른 별도 로컬 테스트·브라우저·API 확인, 읽기 전용 검토의 기록을 정리하고 `production/facts.json`과 네 캡처가 준비된 뒤 실행합니다. 현재 코드와 근거의 일치는 제작자가 확인합니다.

```sh
python3 scripts/build-deck.py --require-screenshots
```

Windows용 글꼴로 다시 만들기:

```sh
python3 scripts/build-deck.py --font "Malgun Gothic" --require-screenshots
```

필요 라이브러리는 `python-pptx==1.0.2`입니다. 출력은 `deliverables/ghcp-agentic-development.pptx`이며 같은 파일을 다시 생성하면 기존 파일을 덮어씁니다. 수작업으로 편집한 PPT는 다른 이름으로 보존한 뒤 재생성하세요.

생성기는 근거 누락·잘못된 자료형·미확인 구현·실패 테스트·검증 건수 부재가 있으면 멈춥니다. `copilotReview`가 false이면 검토 미확인으로 표시합니다. 숫자를 추정해 채우거나 통과시키기 위해 값을 바꾸지 않습니다. 최종본에는 `--require-screenshots`를 사용하세요. 이 옵션이 없는 초안에서 캡처가 빠지면 “실제 캡처 준비 중”이라고 표시하며, 이를 완성된 실제 화면으로 발표하지 않습니다. 생성 후에는 발표에 사용할 PowerPoint 또는 Keynote에서 12장과 발표자 노트, 한글 줄바꿈, 캡처 식별성, 영상 파일 경로를 확인합니다.
